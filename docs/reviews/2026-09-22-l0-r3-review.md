## 发现

### R3-1 / P1：未知 session 的消息仍绕过资源授权并写入回执

位置：`agent_net/node/routers/code_review.py:450`–`:470`，`agent_net/code_review/service_auth.py:133`。

上传接口已拒绝未知 Run，但 POST A/messages 仍在查不到 session 时传空字符串给 require_resource；后者在凭据登记了任意资源范围时放行。隔离复现：coordinator 凭据只授权已有 session S，发送 `session_id=never-authorized-session`、`run_id=unregistered-run` 的合法 accepted receipt（正确身份与必填头），返回 **202** 并持久化。属于同一 R2-2 授权根因在消息入口的残留，不能认为资源授权整体关闭。

修复要求：在消息入口拒绝未知/歧义资源，核对 session、Coordinator、Run/Attempt 的受信任关联；角色许可不替代资源许可。若 Assignment 要创建新的绑定，必须走明确的受授权初始化流程，不能用“查不到”作为放行条件。补未知 session、同身份跨 session、真实 session 配错 Run 的 HTTP 负例，确认拒绝无副作用。

### R3-2 / P1：租约不参与上传校验，且分配有效性未在提交事务内复检

位置：`agent_net/persistence/code_review_store.py:1334`（resolve_assignment_binding）、`:1268`（commit_artifact_with_idempotency）；`agent_net/node/routers/code_review.py:709`–`:777`。

resolve_assignment_binding 没有读取 lease_expires_at，路由只检查 status/epoch/deadline。实测把分配租约设为过去，上传仍 **201**。另在 Vault 写入期间将执行状态改成 cancelled，上传仍 **201**，因为最终登记事务只插 artifact 和更新幂等记录，没有重新核验分配。提前查询不能构成取消/epoch/deadline 的原子围栏。

修复要求：在提交事务中读取并验证同一分配的 worker、Coordinator、Attempt、epoch、租约、deadline、执行状态；失效不得登记新产物或将映射置 committed。外部存储可以先写临时/内容寻址字节，但字节存在不能代替当前授权。补过期租约和“读取绑定后、提交前”取消/换 epoch/过 deadline 的确定性测试。

### R3-3 / P2：同 key 并发上传仍发生主键冲突，返回非契约 500

位置：`agent_net/persistence/code_review_store.py:1225`、`:1273`。

pending 预留允许续用同一 artifact_id，解决了串行存储失败后的重试。但两个同 key 请求均在 pending 阶段取得该 ID 后，commit_artifact_with_idempotency 都无条件 INSERT。使用异步屏障让两请求先完成预留，再串行执行 Vault 写入，以排除 Vault 自身锁竞争，实测结果 **[201, 500]**，失败响应为 `Internal Server Error`。第二请求本应复用已提交结果，不能把合法重放当数据库错误。

修复要求：提交事务内先检查映射及 artifact 的最终状态；同投影已经 committed 时返回原 artifact，未提交才写入，冲突仍严格拒绝。补两个真实并发同 key 请求、相同/不同业务投影，以及多次失败后并发恢复。不能只 catch IntegrityError 后无条件返回成功。

### R3-4 / P2：幂等比较仍是原始字节/完整信封，不是契约规定的业务投影

位置：`agent_net/node/routers/code_review.py:739`；`agent_net/persistence/code_review_store.py:1421`、`:1645`；RC2 §7（当前契约第 147 行）。

产物幂等 request_digest 对 HTTP 原始 JSON 字节计算摘要，导致相同 DTO 仅改变排版仍返回 **409 delivery_conflict**。消息则比较完整 envelope；同 message_id/幂等头、业务内容不变，仅改变信封 created_at，首请求 **202**、重放 **409**。RC2 明确排除信封 message_id/created_at/correlation_id/causation_id，并用固定缺省、递归排序的 JSON 比较其他业务字段。头与 message_id 相等的裁决已经正确实现，但没有替代业务投影规则。

修复要求：统一实现显式业务投影，将认证主体/动作/资源域与幂等 key 分离；产物 artifact_body 字符串本身必须原样参与比较，不能重序列化产物内部内容。补外层键序/空白变化、仅追踪字段变化的合法重放，以及 payload/目标变化必须 409 的反例。相同重放应保持原 Receipt/结果，不重新生成业务时间。
