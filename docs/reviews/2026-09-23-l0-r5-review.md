### R5-1 / P2：Coordinator 绑定为空时，事务跳过身份比较

位置：`agent_net/persistence/code_review_store.py` 的 `_verify_assignment_in_transaction()`：

```python
if expected_coordinator_id and (coordinator_id or "") != expected_coordinator_id:
```

当入口解析出的 `external_coordinator_id` 是空字符串时，条件不会执行。`bind_execution_assignment()` 接受并保存空 ID，上传入口也未拒绝。评审方用受信任登记函数先将同一 execution 绑定到空 Coordinator ID，随后在 Vault 写入阶段改绑为有效的其他 Coordinator（Run、Attempt、epoch 等不变）。旧请求仍返回 **201，登记 1 条 artifact**。测试全程使用临时数据库与真实 ASGI/SQLite 路径；见 [独立探针](l0_r5_repro.py)。

RC2 §1 要求 `external_coordinator_id` 来自受信任注册，并把 Coordinator 放入 Run/Attempt 唯一关联键；§4 上传围栏要求在提交事务内比较 Coordinator 身份。空 ID 不能作为“无需比较”信号。建议绑定入口拒绝空 Coordinator ID，上传入口对既有空绑定 fail-closed，并在事务内无条件比较已解析的预期值与当前值。补一条空值转有效值的负例。该问题仅在非法或不完整的受信任绑定记录下触发，故列 P2；普通非空 Coordinator 改绑已被正确拦截。
