# Agent Workflow | Agent 协作流程

> 本文合并原 `docs/roles/*` 与 `docs/processes/*`。角色与流程只保留执行所需规则，详细项目状态见 [project-status.md](project-status.md)。

## 角色职责

| 角色 | 核心职责 | 主要输入 | 主要输出 |
|------|----------|----------|----------|
| 设计 Agent | 架构设计、ADR、接口契约、设计文档、文档治理 | `AGENTS.md`, `docs/architecture.md`, `docs/roadmap.md`, `docs/adr/`, `docs/contracts/` | ADR、设计文档、接口契约、设计答疑 |
| 开发 Agent | 代码实现、API、测试、开发状态同步 | 已批准设计、`CLAUDE.md`, `agent_net/CLAUDE.md`, `docs/api-reference.md` | `agent_net/` 代码、`tests/` 测试、`CHANGELOG.md` |
| 评审 Agent | 设计评审、代码审查、安全审计、质量把关 | ADR、设计文档、代码 diff、`SECURITY.md`, `docs/architecture.md` | 评审意见、批准/驳回结论、风险记录 |
| 测试 Agent | 测试设计、测试执行、缺陷记录、回归验证 | `tests/CLAUDE.md`, `docs/api-reference.md`, 代码变更、评审意见 | 测试报告、缺陷记录、测试规范更新 |

## 禁止事项

| 角色 | 禁止事项 |
|------|----------|
| 设计 Agent | 不直接改生产代码；不绕过评审修改已批准 ADR；不直接改版本路线图 |
| 开发 Agent | 不实现未经批准的架构变更；不跳过测试；不绕过 Daemon 直接操作存储；不暴露私钥 |
| 评审 Agent | 不直接替设计/开发改正文档或代码；不跳过检查清单；不在未审完时批准 |
| 测试 Agent | 不直接改生产代码；不使用真实网络环境做隔离测试；不在测试失败时标记完成 |

## 设计评审流程

```text
提交评审请求 -> 评审审查 -> 反馈记录 -> 修改确认 -> 批准/驳回 -> 设计答疑 -> 交付开发
```

检查清单：

| # | 检查项 | 说明 |
|---|--------|------|
| 1 | 架构一致性 | 是否与 `docs/architecture.md` 和既有模块边界一致 |
| 2 | ADR 遵循 | 是否与已采纳 ADR 冲突 |
| 3 | 安全性 | 私钥隔离、签名验证、访问控制、加密通信是否明确 |
| 4 | 测试要求 | 是否说明新增测试和验收路径 |
| 5 | 外部接口 | 是否影响 Giskard/OATR/QNTM/MEEET 等契约 |
| 6 | 文档同步 | 是否更新 `project-status`、`requirements`、`api-reference` 等受影响文档 |

设计答疑只澄清实现细节、边界条件、性能可行性和兼容性。推翻已批准架构必须走新 ADR 或设计变更评审。

## 代码评审流程

```text
开发完成 -> 提交评审 -> 评审审查 -> 反馈记录 -> 修复阻塞问题 -> 修复确认 -> 批准
```

触发条件：

| 情况 | 是否必须评审 |
|------|--------------|
| 新功能实现完成 | 必须 |
| 安全、密码学、Token、签名、权限变更 | 必须 |
| HTTP API 请求/响应变更 | 必须 |
| 多模块重构 | 必须 |
| 纯文档修改 | 可走快速路径 |
| 测试补充且不改功能代码 | 可走快速路径 |

代码评审检查清单：

| # | 检查项 | 说明 |
|---|--------|------|
| 1 | ADR/设计合规 | 实现是否符合已批准设计 |
| 2 | 安全性 | 鉴权、私钥、签名、防重放、敏感信息处理 |
| 3 | 正确性 | 边界条件、异常处理、状态一致性 |
| 4 | 测试覆盖 | 新功能、修复点、失败路径是否有测试 |
| 5 | API 一致性 | 是否同步 `docs/api-reference.md` 和 SDK |
| 6 | 代码规范 | 是否符合 `CLAUDE.md`、`agent_net/CLAUDE.md` |

问题分类：

| 类型 | 处理要求 |
|------|----------|
| 阻塞性 | 必须修复，且补测试 |
| 建议性 | 可本次修复或记录后续 |
| 信息性 | 仅记录，无需处理 |
